# Проект

Этот проект представляет собой современную интерпретацию Minecraft на движке Godot. Основные цели проекта — абстрактная простота и высокая производительность. 

## Архитектурные правила
- Семантическая фигура - класс, дочерний от `SemanticShape`.
- Основная игровая механика -- алхимия. Алхимия работает по принципу взаимдействия фигур. Если фигура дома пересеклась с фигурой взрыва, то фигура дома должна заменить себя на фиугу разрушеного дома.
- Связь между фигурами через add_owned_shape должна определять зависимую фигуру. Если владеющая фигура при разрушении должна оповестить какую-то фигуру(стена дома должна оповестить дом, если она разршена), то эта фигура называеться зависимой и должна быть внесена в owned фигуры для владеющей.
- Связь между фигурами через add_owned_shape может быть двусторонней и односторонней. Фигура дома должна быть оповещена, если фигуру стены входящей в состав дома разрушели. И наоборот, если фигура дома была разрушена - стена, входящяя в состав дома должна быть оповещена. 
- Список owned определяет направление обхода: уведомления об изменениях и реакции затрагивают только те фигуры, которые явно указаны в списке owned текущей фигуры. Родительская фигура вызывается только в том случае, если она сама указана в списке owned дочерней фигуры.
- propose_shape_change — единственная точка входа для фундаментальной замены (например, когда стена становится разрушеной стеной). Обычные изменения параметров распространяются самой фигурой по списку owned через notify_shape_changed(). 
- Положение фигуры определяется двумя координатами: координатами её октодерева и её собствеными внутри октодерева. Предполагается, что фигуры внутри своего октодерева неподвижны(как дерево неподвижно в координатах планеты), что делает октодерево началом локальной системы отсчёта.
- Если предполагается движение фигуры относительно других систем отсчёта, то необходимо создать ей своё октодерево в on_register(). Движок автоматически свяжет координату фигуры с её координатой октодерева.
- Для создания, обновления, удаления октодерева нужно обращаться к функциям класса-куратора октодеревьев `ShapeSpatialManager`.(пример вызова API октодерева смотреть в реализации класса `PlanetShape`)
- Фигура может обладать визуальным мешем, коллизией, алхимической зоной(класс `AlchemyArea3D`). Для их создания необхоидмо запросить отрисовку через `WorldMesh::request_render`, указав генераторы мешей в соответсвующий аргумент.

## Рендеринг и физика
- Все визуальные меши, коллизии и алхимические зоны создаются только через `WorldMesh::request_render`.
- Аргументы `request_render`: visual, collision, area, material. Пустой генератор означает, что соответствующая нода не создаётся.
- `collision_generator` создаёт `StaticBody3D` с `CollisionShape3D`; `area_generator` создаёт `AlchemyArea3D` с `CollisionShape3D`, но не твёрдую коллизию.
- `AlchemyArea3D` участвует только в алхимических пересечениях и не удерживает `CharacterBody3D` в `move_and_slide()`.
- Для алхимических зон использовать `ConvexPolygonShape3D` или примитивы. `ConcavePolygonShape3D` полый и не подходит для `Area3D`, даже с `backface_collision`.
- `backface_collision` относится к односторонним граням статичной коллизии и не превращает полую форму в объём.
- Коллизия поверхности строится из того же меша, что и визуал. При расхождении проверять `target_mask`, token и активный чанк.
- Raycast инструментов должен работать только с телами; `Area3D` нужны только для сигналов алхимии.

## Системы координат
- Октодерево -- локальная система отсчёта; вершины меша строятся в координатах фигуры, а рендер-ноды ставятся в `shape_origin`.
- `SemanticShape::get_position()` -- позиция фигуры внутри октодерева; позицию самого октодерева задаёт владелец через `ShapeSpatialManager::create_octree()`.
- Для движущихся фигур своё октодерево создаётся в `on_register()`; движок связывает координату фигуры с координатой октодерева.
- Godot камера смотрит по `-Z`; третий столбец `Basis` -- направление "назад". Из `forward` строить `right = forward.cross(up)`, `backward = right.cross(up)`.
- Перевод между global-координатами и координатами октодерева выполнять через узлы октодерева, а не вручную в фигурах.

## Чанки и LOD
- `ChunkOctree` обновляет LOD по позиции камеры и уведомляет пользователей через `SemanticWorld::on_zone_changed()`.
- При `split()` старые меши и запросы чанка удаляются; при `collapse()` удаляются потомки.
- `WorldMesh` использует token на пару `(shape_id, chunk_id)`; генерация асинхронная, устаревшие результаты отбрасываются через `is_current()`.
- Любое изменение SDF должно вызывать `notify_shape_changed()` и приводить к инвалидации и перерисовке затронутых чанков.
- Родительский чанк и дочерний чанк не должны одновременно держать рендер одной и той же фигуры.

## Алхимия
- Пересечение алхимических зон приходит через `AlchemyArea3D::_on_area_entered()`.
- `evaluate_alchemy()` не меняет мир напрямую; он возвращает фигуру-замену или `nullptr`.
- Фундаментальная замена идёт только через `SemanticWorld::propose_shape_change()`; после замены перестраивается `owned`-граф.
- Разделение зон вызывает `on_alchemy_separation()` у обеих фигур.
- Обычные изменения параметров распространяются через `notify_shape_changed()` строго по списку `owned`.

## Игрок и камера
- Поворот по мыши обрабатывается в `Player::_input()`; без `MOUSE_MODE_CAPTURED` относительное движение мыши не применяется.
- Yaw вращает тело игрока, pitch -- только `camera_pivot`.
- `PlayerMovement` читает направление движения из базиса тела; выравнивание к гравитации меняет этот базис.
- Направление гравитации приходит от `GravityShape`, с которым связан `PlayerFieldShape`.
- При подозрении на лишнюю коллизию проверять `get_slide_collision()` и класс реального `collider`, а не догадываться по визуалу.

## Сборка и регистрация
- `SConstruct` сам находит `.cpp` и классы по совпадению имени файла и папки; новый класс без совпадения не попадёт в `ClassDB`.
- `game/generated/auto_register.gen.h` генерируется автоматически и не редактируется вручную.
- Синглтоны регистрируются из `game/singletons`; порядок регистрации задаётся `SConstruct`.
- Сборка не заменяет проверку физики: если поведение зависит от `PhysicsServer`, запускать проект только в headless-режиме.
